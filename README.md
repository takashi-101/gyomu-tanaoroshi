# 業務棚卸し・事務引継ぎ記録ツール

公開URL：https://takashi-101.github.io/gyomu-tanaoroshi/ 　見本データを読み込むと、入力しなくても使い方を確かめられます。

自治体・官公庁の事務職場で、現場の担当者が自分の業務を棚卸しし、経験が要る業務の判断の分かれ目を事務引継ぎ記録として残し、BPRの効果を係単位の残業の変化で確かめるための道具です。

HTMLとJavaScriptだけで作っています。インストールもビルドも要らず、`index.html` をブラウザで開くだけで動きます。ネットにつながらないPCでもそのまま使えます。

## 誰が何に使うか

| 使う人 | 使う場面 |
|---|---|
| 現場の担当者（職員） | 係の業務を作業単位で棚卸しし、区分とチェックを付ける。経験が要る業務について事務引継ぎ記録を書く |
| 係長・課長 | 月の作業時間、負担の大きさ×着手しやすさの4区分を見て、係で取り組む業務を決める |
| DX・行革の担当者 | 各係が書き出したJSONを「JSONを追加で取り込む」で集め、係ごと・課ごとに横並びで見る。改善の前後の値と係単位の残業の変化で効果を確かめる |

区分（定型／経験が要る、要る／要らない、AIに任せる候補か など）を付けるのも、どの業務に取り組むかを決めるのも現場の担当者です。ツールは数字を並べ、印を出すところまでを受け持ちます。

## 機能

### 1. 業務棚卸し
- 業務棚卸し票：業務名、大分類（工程）、担当（課名・係名と役割。個人名は入れない）、手順、頻度（日・週・月・年と回数）、1回の所要時間（分）、件数（月）、1件あたりの時間（分）、使う帳票・システム、課題メモ（滞留・手戻り・割り込みで中断する箇所など）
- 月の作業時間の計算の方法を、業務ごとに選べます
  - 頻度×1回の所要時間：回数で量が決まる業務（例：日に1回の審査、月1回の資料作成）
  - 件数（月）×1件あたりの時間：件数で量が決まる業務（例：窓口での証明書の交付、郵送請求の処理）
  - 前の版のデータ（計算の方法の欄がないもの）は「頻度×1回の所要時間」として計算します
- 現場が付ける区分：定型／経験が要る、要る／要らない、AIに任せる候補か（はい・いいえ・分からない）、担当の異動・退職が近いか
- 負担の大きさ（6項目）と着手しやすさ（6項目）のチェック。それぞれ3つ以上で「負担大」「着手しやすい」と表示
- 一覧表示、並べ替え（見出しを押す）、絞り込み（係・大分類・区分・判定・語句）
- 書き出し・読み込み：JSON（全データの控えと受け渡し）、CSV（業務棚卸し票の一覧。Excelで開ける BOM 付き UTF-8）
  - 「JSONを読み込む」は、ブラウザ内のデータをファイルの内容で置き換えます
  - 「JSONを追加で取り込む」は、今のデータを残したまま、他の係が書き出したJSONの業務と係単位の残業の行を足します。複数のファイルをまとめて選べます
  - 同じ業務（同じID、または課名・係名・業務名がすべて同じもの）は重ねて取り込まず、取り込んだ件数と取り込まなかった件数・業務名を報告します。係単位の残業の行は、課名・係名・前後の期間がすべて同じものを重なりとして扱います
  - 前の版で係名に「会計課 会計係」のように課名と係名を空白で区切って書いたデータは、読み込むときに課名と係名に分けます

### 2. 事務引継ぎ記録
- 「経験が要る」と区分した業務だけが対象。担当の異動・退職が近い業務を一覧の先頭に表示
- 記録の欄：判断の分かれ目（どこで・何を見て・どう決めたか）、そう判断した理由、他のやり方を取らない理由、例外の扱い、渡せない部分とその理由、次の人への手順（言葉にできた部分だけ）
- 「渡せない部分」は空欄のままでも保存できます。書くかどうかは本人が決めます
- 事務引継書の印刷（業務ごとに1枚、A4縦の表形式）。一覧から全件をまとめて印刷することもできます。PDFにする場合は、印刷の画面で「PDFに保存」を選びます
  - 記載が長い業務は2枚目にわたることがあります

### 3. 残業の見える化
- 月の作業時間の多い順の一覧。業務ごとに選んだ方法で計算します（頻度は月あたりの回数に換算×1回の所要時間、または件数（月）×1件あたりの時間）
  - 換算：日次は月20日、週次は月4.33週（52週÷12か月）、年次は12で割る。日数・週数は画面の「換算と印の設定」で変更できます
- 改善候補の印：月の作業時間が基準（既定10時間）以上で、かつ「定型」「要らない」「AIに任せる候補」のどれかが付いた業務
- 負担の大きさ×着手しやすさの4区分：最優先の改善候補／すぐに着手できる候補／中長期の改善候補／優先度が低い
- 業務ごとの改善の前と後：1回の所要時間、工程数、手戻り・差戻しの件数（月）、対応できる職員の数、手順書の有無
- 係単位の残業：改善の前と後の残業時間（月）と残業した人数。月に減った時間と減った人数を表示
- 係ごと・課ごとの合計：業務の件数、月の作業時間、改善の前と後の残業時間と残業した人数を、係ごと・課ごと・全体で足し上げて表示

### 4. AIによる聞き取り支援（ローカルLLM）
- 自分のPCで動く Ollama（`http://localhost:11434`）につながっているときだけ使えます。つながっていないときはボタンが押せない表示になり、他の機能はそのまま使えます
- 事務引継ぎ記録の内容をもとに、経験知を深めるための聞き取り質問の下書きを作ります
- 質問は一問一答で終わらせず、「事実の確認 → なぜそう判断したのか → 他のやり方ではなぜだめなのか → 例外と判断が変わる条件」の順に、本人の答えを受けて1段ずつ深めます
- 質問は、記録の対象の業務を実際に行う場面について聞くようにモデルに指示しています。業務ではなく記録の書き方などを聞いている質問は表示せず、除いた数を知らせます
- 表示する段階は、質問の中身（「なぜ」「理由」を聞いているか、他のやり方や例外を聞いているかなど）に合わせて決めます。モデルが頼んだ段階と違う質問を作ったときも、中身どおりの段階で表示し、そこから次の段階へ深めます
- AIは質問を作るだけで、記録の欄には書き込みません。答えは本人が書き、必要なら「自分の答えをこの欄に追記」で記録の欄に移したうえで、本人が保存します
- モデル名は「接続の設定」で変えられます（既定は `gemma3:4b`。メモリ16GBのノートPCでの動作記録は [local-llm-record](https://github.com/takashi-101/local-llm-record/tree/main/genai) を参照）

### 見本データ
- 上部の「見本データを読み込む」で、架空の係（会計課 会計係、市民課 窓口係）の業務10件を表示できます。入力しなくても各画面の使い方を確かめられます
- 見本データを読み込むと、ブラウザ内のデータは置き換わります。先に「JSONで書き出す」で控えを取ってください

## 動かし方

### 公開URLで見る場合
https://takashi-101.github.io/gyomu-tanaoroshi/ をブラウザで開きます。上部の「見本データを読み込む」を押すと、架空の係の業務10件が表示されます。業務のデータを入力して使うときは、次の「ファイルを開くだけで使う場合」の方法で、手元のPCに置いたファイルを開いてください。聞き取り支援（ローカルLLM）は、手元のファイルを開く形で動作を確かめています。

### ファイルを開くだけで使う場合
1. このリポジトリをダウンロードします（GitHubの「Code」→「Download ZIP」で取得し、展開）
2. 展開したフォルダの `index.html` を、Microsoft Edge か Google Chrome で開きます（ダブルクリック、またはブラウザにドラッグ）

### ローカルLLMを使う場合（Windows）
聞き取り支援を使うときだけ必要です。使わない場合は設定しなくても他の機能はすべて動きます。

**1. Ollama を入れてモデルを取得する**

Ollama の公式サイトから Windows 版を入れたあと、コマンドプロンプトか PowerShell で次を実行します（初回のみ。モデルのダウンロードにネット接続が要ります）。

```bash
ollama pull gemma3:4b
```

別のモデルを使う場合は、ここで取得したモデル名を、ツールの「接続の設定」のモデル名に入れてください。

**2. 接続元を許可する（OLLAMA_ORIGINS）**

ブラウザで開いたファイル（`file://`）から Ollama に接続すると、ブラウザは接続元を `null` として送ります。Ollama が既定で許可している接続元（`http://localhost`、`file://*` など）には `null` が含まれないため、環境変数 `OLLAMA_ORIGINS` で許可します。

1. タスクバーの Ollama のアイコンを右クリックし、Ollama を終了します
2. 設定（Windows 11）またはコントロールパネル（Windows 10）を開き、「環境変数」で検索します
3. 「アカウントの環境変数を編集」を選び、ユーザー環境変数に次を追加して保存します
   - 変数名：`OLLAMA_ORIGINS`
   - 変数値：`*`
4. スタートメニューから Ollama を起動し直します
5. ツールを開き直し、上部の表示が「ローカルLLM：接続中」になることを確かめます。ならない場合は、記録画面の「接続を確かめる」を押してください

ネットにつながったPCでは、使い終わったら、同じ手順で `OLLAMA_ORIGINS` を削除し、Ollama を起動し直して設定を元に戻してください（`*` の間は、ブラウザで開いたどのWebサイトからも、このPCの Ollama に接続できる状態になるため）。

変数値は `*` にしてください。`*` はすべての接続元を許可する値で、接続元 `null` もこれで許可されます。`null` をそのまま変数値に入れると、Ollama の設定の検査で誤りと扱われ、Ollama が起動しなくなります。

`OLLAMA_HOST` は変えず、Ollama が自分のPCからの接続だけを受け付ける状態で使ってください。

## データがPCの外に出ないこと

- 入力したデータは、使っているブラウザの保存領域（localStorage）にだけ保存します。サーバーやクラウドには保存しません
- ツールが通信するのは、聞き取り支援を使うときの、自分のPCの Ollama（`http://localhost` または `http://127.0.0.1`）だけです。接続先にそれ以外は指定できません
- `index.html` の Content-Security-Policy で、通信先を、画面を配信している場所（公開URLで開いたときの `version.json` の読み込み用）と `http://localhost:11434`・`http://127.0.0.1:11434` に限っています。CDN、外部のフォント・画像は読み込みません
- 個人名の欄はありません。担当は課名・係名と役割で、残業は係単位で記録します
- 公開URLで開いた場合も、入力したデータはそのブラウザ内に保存され、GitHubには送りません。GitHubに接続するのは、画面のファイルを読み込むときだけです

### 保存についての注意
- データはブラウザごとに別々です。Edge で入力したデータは Chrome では見えません
- ブラウザの閲覧データ（Cookie とサイトデータ）を消すと、入力したデータも消えます。区切りごとに「JSONで書き出す」で控えを取ってください
- 他のPCや他の職員にデータを渡すときは、JSONで書き出したファイルを渡し、相手が「JSONを読み込む」（置き換え）か「JSONを追加で取り込む」（足す）で取り込みます

## 動作確認（開発用）

`test/` に、Playwright（ブラウザの自動操作）で各画面の動作を確かめるスクリプトと、Ollama の応答の形をまねた仮のサーバー（`test/mock-ollama.js`）があります。ツールの利用には不要です。

```bash
for n in 1 2 3 4 6 7; do node test/layer$n.test.js; done
node test/unsaved.test.js
node test/pages.test.js
node test/merge.test.js
node test/calcmode.test.js
node test/assets.test.js
node test/update.test.js
node test/interview.test.js
```

`test/pages.test.js` は、GitHub Pagesと同じく静的なWebサーバーから配信した状態で開いて確かめます（`URL=公開URL` を付けると公開URLで確かめます）。`test/layer4.test.js` は仮のサーバーを自動で起動し、未接続・接続元の拒否（OLLAMA_ORIGINS 未設定の状態）・接続の3つの状態を確かめます。実際の Ollama での確認は、上の「ローカルLLMを使う場合」の設定のあとに行ってください。`test/update.test.js` は、GitHub Pagesと同じく10分間キャッシュしてよいという設定で配信し、ファイルを更新したあとに普通に開き直して新しい版が出るかを確かめます。

### 更新を公開するとき

`css/` や `js/` のファイルを直したら、push の前に次を実行します。

```bash
node tools/stamp-assets.js
```

`index.html` が読み込むCSSとJavaScriptのURLに、ファイルの中身から作った版の印（`?v=…`）を付け直し、画面全体の版を `index.html` と `version.json` に書きます。印を付け直し忘れると `test/assets.test.js` が失敗します。

公開URLで開いたときは、画面が `version.json` をキャッシュを使わずに読み、ブラウザが古い版の `index.html` を使っていると分かったら、`index.html` を取り直して一度だけ開き直します。これで、更新のあとに普通に開き直せば新しい版が出ます（記録の画面に保存していない入力があるときは開き直さず、画面上部で知らせます）。
